# Contract 38.0.0

A host may declare an observation yieldable when admitting foreground children
or returning an Accepted provider handle. A targeted steer ends eligible waits
and becomes model-visible in the same commit. Children continue; later child
terminals notify as background work. Provider handles close without cancellation;
late authenticated receipts only audit. See [the full rule](yieldable-waits.md).

New optional park fields are `yield_on_steer` and `yieldable_children`; yielded
completions carry `yielded_by`. Old readers reject these closed fields. Undeclared
waits keep their scheduling and declaration bytes; the shared long-result
archive correction applies to new candidates of every tool. Record 1, inbox 3, SQL layouts, RunEvent v6
and App Server v5 are unchanged. No SQL migration is required. Route every session
that has written these fields to 0.35.0 or newer, including finished sessions.
Do not rewrite retained records to downgrade them.

The version is major because closed record shapes and declared scheduling change.
Python 0.35.0 is the required implementation. Publication, immutable lock/snapshot
and central adoption remain pending. Frozen Rust 23.0.0 / 0.21.x does not support
this capability; baseline `00f4240786f1adea1dc0c4730da8ddd06a5ab8ac` is unchanged.

Canonical evidence is `fixtures/yieldable_waits.json`, generated by Python's real
kernel producer `scripts/yieldable_wait_fixtures.py`. The closed record schema is
also generated from that producer's schemas. Producer and durable failure-cut
tests must pass before adoption can be recorded.

Callbacks may observe host state read-only; they must not write, publish,
retain or transfer files or send messages. The final committed observation is
authoritative, and replay only reads the receipt. Verified child copies include
the terminal result and sequence/digest. File delivery stays on the host's
existing path. Invalid structured bodies fall back to the marked default.

Provider acceptance recovery adds optional literal-true yield_on_steer to the
closed provider_evidence payload and its authenticated bytes. First acceptance
fixes policy; identical repeats noop, conflicting attachments reject, and query
conflicts fail with provider_result_invalid. Old readers reject declared inbox
values, including embedded input records, before a park is committed. No SQL
migration is needed. Kernel long receipt candidate paths now bind content
SHA-256 as well as the operation owner, shared by ordinary and yielded tools.
Existing committed references remain authoritative and are never overwritten.

Host wake coalesces active execution or starts ordinary recovery. Drivers exit
after a full tree pass makes no progress and receives no wake marker, including
retained children and terminal delivery. Empty recovery may acquire another
lease and emit status notifications. Cancellation intent belongs to its target
turn, and wake failures report the session identity through the host error path.
