# Model completion evidence

These rules are normative for 37.0.0. Only read metadata after normal complete
stream consumption; non-streaming responses expose their metadata after return.
Mid-stream evidence is mutable and is never a completion verdict. Interruption,
early close, callback errors and cancellation retain existing error paths.

Apply the following rules in order:

| Final evidence | Kernel result | Sessions |
| --- | --- | --- |
| stream_exhausted=true and stream_terminated=false | ModelStreamInterrupted / Unknown; existing bounded retries and duplicate-cost accounting | All |
| refusal text nonempty, normalized reason is not content_filter | Ordinary Definitive answer; empty content uses refusal as assistant body | All |
| normalized content_filter; or normalized refusal without refusal text | Definitive response-level rejection, no retry or endpoint change | response_rejection=true only; absence/false keeps 0.33.3 behavior |
| stream_terminated=null, including non-streaming and degraded observation | Existing behavior; preserve observation diagnostic | All |
| length / stop / tool_calls / other / null | Existing behavior with evidence | All |

Termination signals establish completeness, not success. finish_reason or [DONE]
alone suffices for a normally consumed Chat Completions stream. Anthropic stop
reason/message_stop and Responses terminal events follow their actual adapter
metadata. Observation degradation without another signal means null (unknown),
not false; vv-llm must be at least 0.10.1.

Ordinary definitive model results retain `raw.completion_metadata` with exactly:
`finish_reason` (original string or null), `finish_reason_normalized` (stop,
length, tool_calls, content_filter, refusal, other, or null), `refusal` (string
or null), `stream_terminated` and `stream_exhausted` (Boolean or null),
`termination_signals` (list of strings or null), and `attributes` (object with
optional `openai_done_observer`: unsupported_stream, unsupported_decoder or
observation_failed). Copy these after consumption; no provider bodies or unrelated
attributes are evidence. Refusal text is answer content and may be retained for
ordinary definitive responses. Content remains primary when both are nonempty.
Response rejection retains only the safe descriptor defined in
[model rejection](model-rejection.md); partial answer text is never evidence.
EOF uses the existing payload-free ModelStreamInterrupted Unknown representation.
Neither EOF nor response rejection advances protected-input coverage. Ordinary
refusal-text answers do advance it when adopted as primary history.

`fixtures/model_completion_evidence.json` is generated by the real Python local
HTTP -> vv-llm -> VvLlmClient -> kernel chain, for declared, false and absent
response policies. It includes stream/non-stream content_filter, refusal text,
Anthropic refusal, missing-termination EOF, DONE-only, finish-only, normal,
observation degradation, length, other and non-stream missing finish_reason.
Frozen Rust 23.0.0 does not support this capability.
